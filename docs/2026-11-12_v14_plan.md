# Plan for trade_aggregation 14 (2026-11-12)

Status: implemented, not released. The changes are breaking, so they are
released together as 14.0.0. The section "Result" at the end lists where the
implementation differs from the plan.

## Goal

Make one aggregator usable for two modes with the same code:

- live streaming, where events arrive one by one and the process can
  restart;
- historical replay (backfill), where years of events are aggregated in one
  run.

Both modes must produce the same candles from the same events. A candle must
also say when it was known, so that downstream users do not use information
from the future by accident (lookahead).

Version 13.1 does not support this well. The sections below list the gaps,
the change for each gap, and the reason.

## Gaps in 13.1

1. **Time candles close only when the next trade arrives.**
   - `TimeRule` and `AlignedTimeRule` advance their reference by one period
     per trigger. After a gap of k periods, each of the next k trades closes
     a candle that holds one trade.
   - Periods without trades produce no candle, so a window of n time candles
     does not span a fixed clock time.
   - The close timestamp of a time candle is the last trade, not the end of
     the period.
   - A quiet market delays the candle until the next trade. A live consumer
     cannot close the candle on a clock or a heartbeat.
   - `TimeRule` takes the first trade as its reference, so its candles
     depend on where the stream starts. A replay that starts at another
     point gives other candles.
   - Timestamp 0 means "not started" (`reference_timestamp == 0`), and
     alignment uses `%`, which is wrong for negative timestamps.
2. **`Adaptive` targets the harmonic mean duration.** It averages the
   activity per millisecond, `threshold / duration`. When candle durations
   are skewed (bursts close candles in milliseconds, calm periods hold one
   for hours), this produces far fewer candles than the target. It also
   assumes that the activity grows linearly with time. Net flow and price
   moves grow with the square root of time.
3. **Rules receive a candle that no rule reads.** `AggregationRule<C, T>`
   passes the candle to `should_trigger`, but no built-in rule uses it. The
   parameter couples every rule to one candle type, so a rule cannot be
   reused with a dummy candle or another event type without a wrapper.
4. **Only trades can drive the aggregation.** `TakerTrade` is the only
   event type. Rules and candle components cannot see quotes (best bid and
   ask), so a candle cannot hold quote statistics over the same interval as
   its trade statistics.
5. **A closed candle has no metadata.** The aggregator returns only the
   candle. There is no sequence number, no open and close time of the
   interval, no number of events and no reason why it closed. A consumer
   that must remove duplicates after a replay, or join candles by the time
   they were known, has to build this outside the crate.
6. **No state can be saved.** Rules and the aggregator do not implement
   serde. A restarted process must replay from an earlier point and cannot
   resume in the middle of a candle.
7. **The size unit is implicit.** `By::Quote` sums the raw trade size and
   `By::Base` divides it by the price. That is correct only for inverse
   contracts, where the size is in the quote currency. For linear contracts
   and spot markets the size is in the base currency, and dollar volume
   needs `size * price`, which `By` cannot express.
8. **The `Candle` derive is narrow.**
   - It implements `ModularCandle` for one concrete input type: `Trade`, or
     the type of a `PhantomData` field named `input`.
   - It needs `ModularCandle` and `CandleComponent` in scope at the call
     site.
   - It panics on invalid input instead of a compile error.
   - There is no plain record of the values, for serialization or a table
     schema.
9. **Components miss statistics of the path inside a candle,** for example
   quote volume, realized variance of returns and the largest trade. Some
   existing components have defects:
   - `Vpin` is public, and all its methods are `todo!()`.
   - `VolumeBuys` counts a trade of size `+0.0` as a buy.
   - `TimeVelocity` rounds the duration down to whole seconds.
   - After a reset, `Open`, `High` and `Low` keep the values of the previous
     candle, so an empty candle shows stale prices.

## Changes

The changes are in this order. Each step is one revision that builds and
passes the tests by itself.

### 1. Event traits and a rule trait without the candle

- New trait `Timestamped` with `fn timestamp(&self) -> i64` and the
  required associated constant `TIMESTAMP_RESOLUTION`.
  - Why: rules that close on a clock need the resolution without an event
    (see step 3).
  - Why required: a silent default of milliseconds is wrong for every source
    with nanosecond timestamps.
- `TakerTrade: Timestamped` keeps `price` and `size`.
- `AggregationRule<E>` has `should_trigger(&mut self, event: &E) -> bool`,
  without the candle.
- `ModularCandle<E>` and `CandleComponentUpdate<E>` take any event type.

### 2. Candle envelope and several candles per update

- The aggregator emits `Bar<C>`:
  - `candle`;
  - `seq`: the number of candles that the aggregator closed before this
    one;
  - `open_ts`: the close of the previous candle, or the first event;
  - `close_ts`: the time at which the candle is known;
  - `num_events`;
  - `kind`: closed by the rule, closed at a deadline, or provisional.
- `update(&mut self, event, out: &mut impl Extend<Bar<C>>)`. One event can
  close more than one candle (see step 3).
- `provisional(now)` returns the unfinished candle with its metadata, for
  consumers that need windows that end now.

### 3. Deadlines, watermarks and gaps

- `AggregationRule` gets three provided methods:
  - `deadline(&self) -> Option<i64>`: the time at which the rule closes the
    candle without another event;
  - `on_deadline(&mut self)`: the aggregator closed the candle at the
    deadline;
  - `skip_to(&mut self, timestamp)`: no events until `timestamp`.
- `advance_to(watermark, out)` closes every candle whose deadline has
  passed. `update` calls it before it applies an event, so an event after
  the end of a period never goes into that period, whatever the
  `TriggerTrade` setting.
- Gap policy: `Gaps::Skip` (no candles for empty periods) or
  `Gaps::Flat { max_candles }` (flat candles at the previous close, at most
  `max_candles` per gap).
- Time rules:
  - `Option` instead of the 0 sentinel;
  - `rem_euclid` for the alignment;
  - an optional offset, so that for example weekly candles can start on a
    Monday;
  - the same half-open interval `[start, end)` for both time rules;
  - the resolution comes from the event type, not from the constructor.
- Combinators forward deadlines: `AnyRule` closes at the earlier deadline,
  and `MaxDuration` closes at `open + max` without a trade.
- `Open`, `High` and `Low` carry the last price over a reset, so an empty
  candle is flat at the previous close.
- A fixed boundary (for example UTC midnight) is
  `AnyRule<R, AlignedTimeRule>`. The state at that boundary is a
  reproducible checkpoint.

### 4. Pacing on the arithmetic mean

- `Adaptive` averages the inverse activity, `duration / threshold^p`, and
  sets `threshold = (target / mean)^(1/p)`. This targets the arithmetic
  mean duration.
- `Scaling::Linear` (p = 1) is for volume and trade counts.
  `Scaling::Diffusive` (p = 2) is for net flow and price moves, which grow
  with the square root of time.
- Why: the arithmetic mean is what "candles of about 1 minute" means to a
  user (about 1440 candles per day). With skewed durations the harmonic mean
  is far from it.

### 5. Serializable state

- With the `serde` feature, every rule, the rule parameters, the aggregator
  and `Bar<C>` implement `Serialize` and `Deserialize`.
- Test: an aggregator that is saved and restored at random points produces
  the same candles as one that runs without interruption.

### 6. Explicit size unit

- `TakerTrade` gets the required associated constant
  `SIZE_UNIT: SizeUnit` (`Base` or `Quote`). It states the unit of
  `size()`.
- `By::Base` and `By::Quote` then mean the unit of the sum, for both linear
  and inverse contracts. `TakerTrade::base_size()` and `quote_size()` are
  provided.

### 7. Candle derive and candle hooks

- The derive implements `ModularCandle<E>` for every `E` that all
  components accept.
- It uses absolute paths (`::trade_aggregation::...`), so nothing has to be
  in scope.
- It reports invalid input as a compile error.
- `#[candle(record = Name)]` also generates a plain record struct of the
  values and a `FIELDS` constant with the field names.
  `#[candle(record_derive(...))]` adds derives to that struct, for example
  serde.
- `CandleComponentUpdate::close_at(&mut self, timestamp)` (default: no-op)
  runs before a candle is emitted. Statistics that are weighted by time
  integrate until the end of the candle.

### 8. Trade components and fixes

- New components:
  - `QuoteVolume` and `BaseVolume`;
  - `MaxSize` (the largest trade);
  - `RealizedVariance`, `BipowerVariation` and `RealizedQuarticity` of log
    trade returns. The return from the last trade of the previous candle
    counts, so no return is lost at a candle boundary.
- Fixes: remove `Vpin`, fix `VolumeBuys` and `TimeVelocity`.

### 9. Market events and quote components

- `BestQuote: Timestamped` with the bid and ask prices and sizes.
- `MarketEvent<T, Q> { Trade(T), Quote(Q) }`. Its trade and its quote must
  have the same timestamp resolution, which is checked at compile time.
- `AsTrade` and `AsQuote` project an event to a trade or a quote:
  - Trade rules and trade components act on trades and ignore quotes.
  - Time rules act on every event.
  - A plain `TakerTrade` type keeps working without a wrapper.
- New quote components:
  - mid price open, high, low and close;
  - realized variance of the weighted average price (WAP) returns;
  - time-weighted relative spread;
  - time-weighted level-1 imbalance;
  - order flow imbalance (Cont, Kukanov and Stoikov);
  - number of quote updates;
  - effective spread of trades against the mid price.
- Order book depth is out of scope. A full book is the wrong state for a
  candle component. A caller can send summaries of the book as its own
  event type.

## Not in the crate

These belong to the caller:

- the wall clock time when a candle was emitted;
- the identity of the series (exchange, symbol);
- the hash of the rule configuration;
- the merge and reorder of several input streams;
- the choice of timestamp when a source has no exchange timestamp.

The crate requires events in time order and asserts it.

## Result

All steps are implemented, one revision each, except step 3, which is two
revisions (the deadline mechanism with the time rules, then the
combinators). Differences from the plan:

- `CandleComponent` has an associated `Value` type instead of a type
  parameter. The derive needs it to name the return type of a getter. The
  old guess from the first generic argument was wrong for `Trades<T>`.
- `MaxDuration` closes at `open + max_duration`, so a candle covers
  `[open, open + max)` like the time rules. Before, it closed at the first
  trade after that time.
- `AllRule` has a deadline only after one of its rules has triggered.
  Before that, the deadline of the other rule alone does not close the
  candle, so that rule triggers on the next event, as in 13.1.
- `Bar::open_ts` is the close of the previous candle. With `Gaps::Skip`,
  the candle after a gap therefore includes the gap.
- `MillisecondPeriod` implements `TryFrom<u64>` and deserializes through
  it, so a zero period is rejected.
- `Quote` is a simple `BestQuote` with a millisecond timestamp, the
  counterpart of `Trade`.
- The values of the quote components are `Option`s: `None` while no quote
  has arrived. The time-weighted averages return the current value if the
  candle covers no time.
- `TimeRule` stays. Its documentation recommends `AlignedTimeRule` for
  candles that do not depend on the start of the stream.
- The `chrono` feature did not compile in 13.1 (`OpenDateTime`). It is
  fixed, and CI tests all features.

Not done:

- Order book depth (see step 9).
- Deserialization does not check the invariants of the rule parameters.
  Deserialize only state that this crate serialized.
